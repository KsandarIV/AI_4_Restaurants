How the voice bot code works

The audio pipeline piece by piece: each stage says which file does it and which queue it uses to talk to the next one. In jargon: producer-consumer over asyncio.Queue.

The journey of one sentence

File by file, in one line

FileRole in plain words
pipeline/server.pyThe front door: WebSocket with the browser, the test pages, /health, /ready, /diag. Loads STT/TTS once for all calls.
pipeline/session.pyThe conductor: three parallel tasks, queues between them, barge-in and clean shutdown.
vad.pyThe ears: understands when you talk and when you pause (no buttons).
stt.pyThe incoming translator: voice → text with Whisper, on this machine.
orchestrator.pyThe director: the chat bot's conversation — registration phase, anonymise, ask the BE, restore names.
contacts.py · anonymizer.pyPorts of the chat bot's contatti.py and anonimizzatore.py (plus spoken-digit handling).
backend.pyThe phone to the central server: sends anonymous text, receives words as a stream.
tts.pyThe voice: text → Italian audio with Piper, sentence by sentence as it arrives.
v2.py · chat_service.pyOn-demand mode: microphone → text → chat conversation → speaker; optionally on top of the chat service.
live_client.pyA call from any PC without a browser, with automatic reconnection.
diagnostics.py · doctor.py"Why does it not work?": one report for /diag and for the command line.
pii.pyLast-line privacy net: removes e-mails and phone numbers from anything about to be sent.
config.pyThe knobs: a single .env at the repo root for everything.

Why it is built this way

Every stage works while the others go on (no chain of waits): the voice starts before the sentence is finished, and if you interrupt only the current turn is dropped. The abstract interfaces (AbstractSTT etc.) let you swap a model without touching the pipeline — handy in demos and in production.
