Come è fatto il codice del voice-bot

La pipeline audio spiegata pezzo per pezzo: ogni tappa dice quale file la fa e con quali code parla alle altre. In gergo: produttore-consumatore su asyncio.Queue.

Il giro di una frase

File per file, in una riga

FileRuolo spiegato semplice
pipeline/server.pyLa porta d'ingresso: WebSocket col browser + pagine /prova-vocale e /tech*.
pipeline/session.pyIl direttore d'orchestra: tre compiti in parallelo, code tra loro, interruzione e spegnimento pulito.
vad.pyLe orecchie: capisce quando parli e quando fai pausa (niente pulsanti).
stt.pyIl traduttore in entrata: voce → testo con Whisper, sul posto.
orchestrator.pyIl regista: ricorda la conversazione, scorciatoie veloci (menu, orari), dialogo col BE.
backend.pyIl telefono col server centrale: invia testo anonimo, riceve parole in streaming.
tts.pyLa voce: testo → audio italiano con Piper, frase per frase mentre arriva.
pii.pyLa privacy: cancella email/telefoni prima di inviare qualsiasi cosa.
config.pyLe manopole: un solo .env in root per tutto.

Perché è fatto così

Ogni tappa lavora mentre le altre vanno avanti (niente attese a catena): la voce parte prima che la frase sia finita, e se interrompi si butta solo il turno corrente. Le interfacce astratte (AbstractSTT ecc.) permettono di cambiare modello senza toccare la pipeline — utile in demo e in produzione.
